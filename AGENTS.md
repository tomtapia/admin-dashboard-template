# AGENTS.md

React 19 + Vite 6 + TypeScript admin dashboard. Package manager is **pnpm** (use `pnpm`/`pnpx`, not npm).

## Commands
- `pnpm dev` — Vite dev server (starts MSW mock worker in dev).
- `pnpm build` — runs `tsc -b` (project-references typecheck) **then** `vite build`. There is no separate lint/typecheck script; treat `build` as the typecheck+verify step.
- `pnpm test` — `vitest run` (all tests, jsdom). `pnpm test:watch` — watch mode.
- Run a single test file: `pnpm vitest run src/test/app-router.test.tsx`.
- `pnpx shadcn@latest add <component>` — add UI components (config in `components.json`).

## Conventions an agent would miss
- **Path alias:** `@/` → `src/`. Always import via `@/...`, not relative paths.
- **Tailwind v4 (CSS-first):** there is no `tailwind.config.js`. Styling lives in `src/styles.css` via `@import "tailwindcss"`. Don't add a JS tailwind config.
- **shadcn/ui** components live in `src/components/ui`; config style is `new-york`, `rsc: false`. `src/lib/utils.ts` has `cn()` (clsx + tailwind-merge).
- **MSW mocks** are the data layer in dev and in tests. Edit handlers in `src/mocks/handlers.ts` (plus `data.ts`, `browser.ts`). The worker file `public/mockServiceWorker.js` must exist (regenerated by `pnpx msw init public`).
- **Tests fail on any unmocked fetch.** Test setup uses `onUnhandledRequest: "error"` (`src/test/setup.ts`). When adding a feature that fetches, add a handler to `src/mocks/handlers.ts` or the test errors. Every test resets mock state + localStorage in `afterEach`.

## Architecture
- Entry: `src/main.tsx` → `AppProviders` (`src/app/providers.tsx`) → `AppRouter` (`src/app/router.tsx`, lazy-loaded routes).
- Routes under `/app/*` are wrapped by `ProtectedRoute` + `AppShell` (`src/components/layout`). Public route is `/login`; `/` redirects to `/app/overview`.
- Feature modules: `src/features/{auth,theme,overview,users,settings,billing,analytics,team,notifications,transactions,integrations,support}` (contexts + API). `src/pages/*` are route components. `src/components/{ui,layout,shared,settings,users}` are building blocks.
- **Adding a module** (e.g. a new SaaS surface) follows a fixed pattern: (1) add domain types to `src/types`, (2) add seed fixtures + handlers in `src/mocks/{data,handlers}.ts`, (3) add data-access in `src/features/<module>/<module>-api.ts` using `http()`, (4) add the page in `src/pages/<module>-page.tsx` and components in `src/components/<module>/`, (5) register a lazy route in `src/app/router.tsx`, (6) add a nav entry in `src/components/layout/nav-items.ts` (grouped). Every mock endpoint must be covered or tests fail (`onUnhandledRequest: "error"`).
- Reusable building blocks for module pages: `DataTable` (`src/components/shared/data-table.tsx`, generic column-based table) and `DetailDrawer` + `DefinitionList` (`src/components/shared/detail-drawer.tsx`, right-side detail panel). Prefer these over hand-rolled grid tables.
- **Sidebar nav** is grouped (`navGroups` in `src/components/layout/nav-items.ts`): Dashboard (Overview, Analytics), Manage (Users, Team, Billing, Transactions), Engage (Notifications, Support, Integrations), Settings. Icons map via `iconMap` in `src/components/layout/sidebar-nav.tsx` — add new lucide icons there when adding nav items.
- **Auth/session** is stored in `localStorage` key `admin-dashboard-template:session`; **theme** in `admin-dashboard-template:theme`. Tests seed a session by writing `defaultSession` from `@/mocks/data` to that key before `renderApp`.
- Data fetching via TanStack Query (`src/app/query-client.ts`); thin `http()` wrapper in `src/lib/http.ts` throws on non-2xx.
- Forms: React Hook Form + Zod (`@hookform/resolvers`).
